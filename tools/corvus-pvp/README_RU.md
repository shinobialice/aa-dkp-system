# Corvus PvP scanner v3

Пассивный разбор игрового трафика ArcheAge (сервер Corvus, TCP-порт 1239): ник, PvP-честь и
PvP-убийства персонажей вокруг, плюс «кто рядом прямо сейчас».
Программа **только читает** пакеты, которые сервер уже прислал клиенту: ничего не отправляет,
не меняет и не читает память игры.

> Не публикуйте сырые PCAP/ETL и CSV с чужими никами — в репозитории их нет, тесты на реальном
> захвате берут файлы из локальных путей.

---

## 1. Главный вывод: это не «2+2 / 3+3», а один формат — PISC

Число записано блоком **PISC**: один байт флагов и до четырёх целых little-endian.
На каждое значение в байте флагов отведено 2 бита (значение *i* → биты `2i, 2i+1`):

| код | ширина |
|-----|--------|
| `00` | 1 байт |
| `01` | 2 байта |
| `10` | 3 байта |
| `11` | 4 байта (в образце не встречался; ширина взята из эмулятора — помечается в отчёте) |

Биты отсутствующих значений обязаны быть нулями. Честь и убийства — это первые два значения
блока из **четырёх** значений: `PISC4 [PvP-честь, PvP-убийства, ?, ?]`.

Пример из реальной записи: `41 | 3C 02 | 15 | 00 | B7 03`
флаг `0x41 = 01 00 00 01` → `u16, u8, u8, u16` → `[572, 21, 0, 951]`.

Почему старые гипотезы «почти работали»:

* `COMPACT_16` читал убийства как u16 `15 00`. На самом деле это u8 `15` + третье значение блока `00`.
  Число верное только пока третье значение равно 0; при `[572, 21, 5, 0]` старый метод дал бы 1301.
* `FULL_24` читал убийства как u24 `FC 02 00` — это u16 `FC 02` + третье значение `00`.
* «Признак ширины по младшим 3 битам» — это и есть байт флагов PISC: `low3 = 6` (`110`) означает
  «честь u24, убийства как минимум u16», `1` и `5` — «честь u16, убийства u8/u16».
* «Нули Gnomius» и «короткие записи»: флаг `00` → все четыре значения по одному байту
  (`00 | 00 00 00 00` = 0/0, `00 | 10 00 00 00` = 16/0). Никакого маркера там нет — поэтому старые
  сканеры такие записи не находили.

Тем же PISC в записи упакованы списки навыков/пассивок, блок фракции/гильдии/семьи и т.д.

## 2. Формат записи персонажа

Распакованный DD04 = `u16 число_подпакетов` (2 байта перед raw DEFLATE) + поток подпакетов.
Подпакет: `00 ?? | u16 опкод | тело`, **без поля длины** — границы определяются только структурой.

Опкод `0x00EF` — состояние юнита (появление в зоне видимости):

| поле | формат | примечание |
|---|---|---|
| obj_id | u24 | runtime-ID объекта в мире; тот же ID в DD01/0x00AF; **не постоянный** |
| имя | u16 длина + UTF-8 | у NPC/маунтов пусто (`00 00 FF FF …`) |
| вид записи | u8 `0x2A` | у всех игроков |
| char_id? | u32 по смещению +4 от конца имени | вероятно постоянный ID персонажа: для своего персонажа то же значение приходит в DD05 при входе |
| позиция | u32 x, u32 y, u24 z по смещению +22 | те же значения, что в AF |
| масштаб, уровень | f32 `1.0`, u8 уровень, u8 уровень наследия | |
| … | экипировка, внешность, HP/MP | переменная длина, не разбирается |
| **хвост персонажа** | | ищется по собственной структуре: |
| | u8 n_навыков, u8 n_пассивок, 13 байт | |
| | n_навыков ID, PISC-порции по min(4, остаток) | строго возрастают |
| | n_пассивок ID, так же | строго возрастают |
| | i8 rot_x, i8 rot_y, i8 rot_z, u8 `16*пол + раса` | |
| | PISC4 `[?, ?, a2, ?]` | a2 — вероятно титул |
| | PISC3 `[фракция, гильдия, семья]` | у соигроков совпадают гильдия и семья |
| | **PISC4 `[PvP-честь, PvP-убийства, ?, ?]`** | |
| | u16 флаги, u8 | бит `0x0100` → далее ещё 7 байт |
| | 29 × (u32 опыт способности, u8 слот или `FF`) | |
| | u8 n_активных + ID активных способностей | `== {индекс+1 : слот != FF}` |

Последние две строки — **независимая самопроверка**: в каждой записи ровно три слота 0/1/2, и
список активных способностей в точности совпадает с их позициями. Она не зависит ни от ников,
ни от известных чисел.

Цифры по `login_capture.pcap`: цепочка «до чести» сама по себе нашлась 164 раза по всем позициям
всех DD04, а с проверкой блока способностей — **ровно 15 раз, по одной на каждого персонажа**.
Поэтому без этой проверки значения не выдаются (статус `UNCONFIRMED`).

## 4. Появление, присутствие, исчезновение (задача C)

* **Появление**: подпакет `0x00EF` приходит, когда юнит входит в зону видимости (вход в мир,
  телепорт, подход). При входе в город — большими DD04 по 9–16 подпакетов.
* **Присутствие**: DD01/0x00AF — `u16 count + count × 36 байт`
  (`u24 obj_id, u8 1, u32 время_мс, u8, u32 x, u32 y, u24 z, i16 vx, vy, vz, …`).
  Каждый юнит в зоне видимости получает запись **каждые 3,0 с даже стоя на месте**
  (измерено: интервалы 2,99–3,05 с). Свой персонаж — тоже, поэтому есть своя позиция.
  Правило сканера: «рядом» = последняя AF-запись не старше 7,5 с (2,5 периода).

  **Что такое «сигнал» (раньше — «пульс»)**: это и есть такая AF-запись — сервер раз в 3 с
  сообщает клиенту координаты каждого, кто в зоне видимости. Колонка «Сигнал, с назад» — сколько
  секунд прошло с последней. 0–3 с — игрок точно прогружен у вас; больше 7,5 с — сервер перестал
  его присылать (ушёл из видимости, вышел из игры) или захват потерял пакеты.
* **Исчезновение**: явного пакета удаления в 21,7-секундном захвате нет (никто не ушёл).
  Пока это «пульс пропал → `ушёл?`». Данные вашего эксперимента v2.3 с этим согласуются:
  у стоящих игроков в фазе «вдали» ~4 AF-записи (≈12 с пульса), после возвращения — снова
  каждые ~3 с. Пакет удаления ищет команда `discover` (см. эксперимент ниже).
* NPC, маунты и питомцы тоже приходят как `0x00EF`, но с пустым именем, и тоже получают AF.
  Поэтому «ID из AF» ≠ «игроки».
* Масштаб координат: 512 единиц ≈ 1 м (как у старых 3-байтовых координат; скорость бега получается
  ≈6 м/с). Это вывод, а не официальная константа.

## 5. Можно ли нажать кнопку и увидеть 30 уже прогруженных игроков? (задача D)

Ник и PvP есть **только** в `0x00EF`, а он отправляется **один раз при появлении**. Дальше сервер
шлёт только движение/бой. Проверка на `login_capture.pcap` (захват «начинается» позже):

| захват начат через | игроков с ником и PvP | объектов рядом без анкеты |
|---|---|---|
| 0,1 с (до входа в мир) | 14 | 0 |
| 8,9 с | 5 | 18 |
| 12,9 с | 0 | 27 |

* **Только пассивный трафик, захват начат после прогрузки:** видны obj_id и позиции всех, кто
  рядом (AF-пульс), но **без ников и PvP**; игроков от NPC надёжно не отличить.
* **Захват начат до входа в мир** (экран выбора персонажа): видно всех — сервер сам присылает
  анкеты всех вокруг. Программа держит состояние в фоне, кнопка показывает срез «кто рядом сейчас».
* **Уже загружено, но больше не передаётся:** ники/PvP тех, кто был прогружен до запуска —
  они есть только в памяти клиента. Чтение памяти игры здесь сознательно не делается.
* **Как получить их без отправки пакетов:** обычными действиями в игре заставить сервер прислать
  анкеты снова — выйти на экран выбора персонажа и зайти обратно (как в `login_capture`),
  телепортироваться и вернуться, или отойти за пределы видимости и вернуться. Программу при этом
  не закрывать.
* **Чего одним декодером не решить:** PvP-значения — снимок на момент появления (обновляются ли
  они, пока игрок рядом, не проверено); obj_id не постоянен между сессиями; точный радиус видимости
  задаёт сервер; явный пакет исчезновения ещё не найден; если захват пропустил свой `0x00EF`,
  расстояния неизвестны до следующего входа в мир.

## 6. Установка и запуск (Windows)

**Установщик (обычный способ).** Сайт → раздел «Киллкаунт α» (заголовок раздела в меню — ссылка
для администраторов и модераторов) → «Скачать установщик для Windows» → `CorvusScannerSetup.exe`.
Python и Npcap не нужны: программа собрана PyInstaller, а пакеты читает встроенным захватом
Windows (raw socket `SIO_RCVALL`), поэтому при запуске спрашивает права администратора.
Установщик создаёт ярлык на рабочем столе с логотипом сайта и правило брандмауэра Windows
(без него входящие пакеты сырому сокету не видны). Программа не подписана: на «Windows защитил
ваш компьютер» — «Подробнее» → «Выполнить в любом случае». Снимки и настройки лежат в
`%LOCALAPPDATA%\CorvusScanner`.

Установщик собирает GitHub Actions (`.github/workflows/scanner-installer.yml`) на Windows при
каждом изменении этой папки: тесты, сборка, самопроверка `CorvusScanner.exe --selftest`, тихая
установка с проверкой ярлыка и правила брандмауэра, удаление. С `main` файл публикуется в релиз
`scanner-latest`; сайт отдаёт ссылку на него только модераторам. Репозиторий публичный, так что
сам файл релиза технически доступен по прямой ссылке — секретов в нём нет.
Собрать вручную: `cd tools\corvus-pvp; .\packaging\build.ps1 -Version 1.0.1`.

**Скрипты (для разработки).** Python 3.9+ (`py -3 --version`); Npcap (https://npcap.com,
«WinPcap API-compatible Mode») — или без него, запустив консоль от имени администратора.

1. Скопировать папку `tools/corvus-pvp` (или «Архив со скриптами» с той же страницы сайта).
2. **Запустить до входа персонажа в мир**: `START_SCANNER.bat`
   (или `py -3 .\corvus_scanner_gui.py`). Захват стартует сам: Npcap, если установлен, иначе
   встроенный захват Windows.
3. В поле «Мой ник» — свой ник (иначе определяется автоматически по записи входа в мир).
4. Кнопка **«Сканировать рядом»** — таблица: ник, PvP-честь, PvP-убийства, класс, ID гильдии,
   расстояние, статус («рядом»/«появился»/«ушёл?»), «Сигнал, с назад» и возраст анкеты.
   Неизвестное показывается как «—», не нулём.

Офлайн (любой ОС):

```powershell
py -3 .\corvus_scan.py decode   .\login_capture.pcap --csv players.csv --json players.json
py -3 .\corvus_scan.py verify   .\login_capture.pcap --truth .\truth.local.csv
py -3 .\corvus_scan.py nearby   .\login_capture.pcap --radius 80
py -3 .\corvus_scan.py discover .\login_capture.pcap
```

`truth.local.csv` — локальный файл `name,honor,kills` (UTF-8), в репозиторий не кладётся.

Статусы разбора: `OK` — одна подтверждённая структура; `OK_RELAXED_GAP` — подтверждена, но
нестандартный зазор перед списками; `AMBIGUOUS` — несколько подтверждённых вариантов (значения не
выдаются); `UNCONFIRMED` — цепочка без самопроверки (значения только в диагностике);
`NO_PVP_STRUCTURE` — не найдено.

### Класс

Класс — сочетание трёх активных веток из блока способностей записи. Номера веток в пакете:
1 Нападение, 2 Гипноз, 3 Оборона, 4 Сопротивление, 5 Мистицизм, 6 Преследование, 7 Волшебство,
8 Скрытность, 9 Воодушевление, 10 Исцеление, 11 Гнев, 12 Коварство, 13 Стрельба, 14 Танец
(внутренние имена эмулятора: Fight, Illusion, Adamant, Will, Death, Wild, Magic, Vocation, Romance,
Love, Hatred, Assassin, Madness, Pleasure). Номера 5 и 12 пока ни у кого в захватах не встречались —
у таких классов в таблице стоит «?». Русские названия классов берутся из таблицы сайта
(`src/widgets/profile/archetype/classCombinations.ts`); копию для сканера обновляет
`py -3 sync_class_names.py`.

### Киллкаунт за прайм

**Скачать сканер**: страница `/kill-counter/scanner` (ссылка — заголовок «Киллкаунт α» в меню и
строка под заголовком «Сегодня»). Страница и обе ссылки (`/api/killcount/scanner/installer` —
установщик, `/api/killcount/scanner` — архив со скриптами, без снимков и настроек) открываются
только пользователям с тегом «Администратор» или «Модератор»; остальным — 404 или 403.

Каждый прайм:

1. **Начало прайма**: экран выбора персонажа → запустить программу → войти в локацию сбора →
   подождать, пока в строке статуса «анкет игроков» перестанет расти (обычно 5–10 с) →
   **«Сканировать рядом»**. Каждый скан сохраняется в `snapshots\snapshot_<дата>_<время>.json`.
   Программу можно закрыть.
2. **Конец прайма**: снова через экран выбора персонажа — вход в мир обязателен, иначе у сканера
   останутся анкеты из начала прайма (такие игроки не посчитаются, окно покажет их списком
   «Нет свежей анкеты в конце»). Затем «Сканировать рядом».
3. **«Киллкаунт…»**: по умолчанию конец — последний снимок, начало — самый ранний за 8 часов до него.
   «Посчитать и скопировать JSON для сайта» → JSON в буфере обмена (и в `snapshots\killcount_<дата>.json`).
4. **Сайт**: Киллкаунт → «Добавить вручную» → вставить в поле «Вставьте JSON» → проверить
   таблицу и список «Не попали в киллкаунт» → «Сохранить».

Кто попадает в киллкаунт:

* в сканере — игроки, которые есть в **обоих** снимках, по умолчанию только **гильдии того, кто
  сканирует**; сопоставление по постоянному ID персонажа (смена ника на прайме не ломает подсчёт:
  в строке будет и прежний ник, сайт найдёт пользователя по любому из них);
* на сайте — только **пользователи сайта на ролях Милик, Стрелок, Лук, Маг**
  (`src/shared/config/killcountRoles.ts`). Роль определяется по трём веткам класса, которые увидел
  сканер: сайт ищет слот архетипа пользователя с теми же ветками и берёт роль этого слота
  (класс 1/2/3 в профиле); если такого слота нет — основная роль. Хил, Бард, Танцор, Тактик, роль
  не указана или ника нет на сайте — строка убирается, причина видна в списке «Не попали в
  киллкаунт»; вернуть человека можно кнопкой «Добавить» в таблице.

Если между снимками сменился класс, в строку пишется класс в конце, а в комментарий — «класс в
начале: …». Если анкета в начале старше 10 минут, окно предупреждает: в разницу могли попасть
убийства до начала прайма.

Без окна:

```powershell
py -3 .\corvus_scan.py killcount .\snapshots\snapshot_2026-10-17_20-01-12.json .\snapshots\snapshot_2026-10-17_23-02-40.json --out kc.json
```

## 7. Тесты

```powershell
py -3 -m unittest discover -s tests -v
$env:CORVUS_PCAP  = "C:\ArcheAgePvP\login_capture.pcap"
$env:CORVUS_TRUTH = "C:\ArcheAgePvP\truth.local.csv"
py -3 -m unittest discover -s tests -v
```

Синтетические тесты: ширины PISC, запрет лишних битов флага, короткая последняя порция списка,
почему `COMPACT_16/FULL_24` — частные случаи, нули/малые/24-битные/32-битные значения, флаг +7 байт,
отказ выдавать значения при сломанной самопроверке, отсутствие срабатываний на 250 КБ шума,
сборка TCP (перестановка, повторы, переполнение seq), старт захвата посреди сообщения,
PCAP/PCAPNG, трекер присутствия.

## 8. Эксперимент: найти пакет исчезновения и проверить обновление PvP

Один захват ~5 минут, начатый **на экране выбора персонажа**:

1. Запустить захват (для Npcap права администратора обычно не нужны):

   ```powershell
   cd C:\ArcheAgePvP\corvus-pvp
   py -3 .\corvus_scan.py capture --seconds 300 --out .\captures\exp_leave_return.pcap
   ```

   Без Npcap — встроенный `pktmon` (PowerShell **от администратора**):

   ```powershell
   pktmon filter remove
   pktmon filter add AA -t TCP -p 1239
   pktmon start --capture --comp nics --pkt-size 0 -f C:\ArcheAgePvP\exp.etl
   #  ... эксперимент ...
   pktmon stop
   pktmon etl2pcap C:\ArcheAgePvP\exp.etl --out C:\ArcheAgePvP\exp.pcapng
   pktmon filter remove
   ```

2. В игре: войти в мир в городе → 60 с стоять → убежать/улететь от площади **дальше 300 м** →
   60 с → вернуться → 60 с стоять. Записать примерное время ухода и возвращения.
3. Разобрать и прислать **текстовые отчёты** (не PCAP):

   ```powershell
   py -3 .\corvus_scan.py --report decode.txt   decode   .\captures\exp_leave_return.pcap
   py -3 .\corvus_scan.py --report discover.txt discover .\captures\exp_leave_return.pcap
   py -3 .\corvus_scan.py --report near_50.txt  nearby   .\captures\exp_leave_return.pcap --at 50
   py -3 .\corvus_scan.py --report near_200.txt nearby   .\captures\exp_leave_return.pcap --at 200
   ```

`discover` найдёт уходы (пульс пропал) и сообщения, которые упоминают ID ушедших в окне ухода, но
не упоминают оставшихся рядом, — это кандидаты на пакет удаления. `decode` покажет, пришли ли
повторные `0x00EF` при возвращении и изменились ли в них PvP-значения.

## 9. Что не доказано

* ширина кода PISC `11` (4 байта) — в образце не встречалась;
* смысл значений 3–4 PvP-блока, блока A, 13 байт перед списками, 7 доп. байт;
* «фракция/гильдия/семья» — по совпадениям у соигроков, не по документации;
* число способностей 29 и зазор 13 — константы этой версии клиента (если поменяются, сработает
  запасной поиск зазора, а иначе статус `UNCONFIRMED`/`NO_PVP_STRUCTURE`, но не неверные числа);
* масштаб координат 1/512 м и порог присутствия 7,5 с — выведены из одного захвата.
